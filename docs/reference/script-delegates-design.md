This is a proposed bounded increment, not an implementation or compatibility approval. No product, host API, CI driver, manifest, contract, parser or status change accompanies this document. The primary sources below are `src/3rdparty/squirrel/squirrel/` in that exact original revision. ## Recommendation and alternatives

Implement explicit table-delegate ownership and ordinary delegation first, with expression membership as a separate small prerequisite atom. Then implement the nested metamethod execution boundary in a separately approved follow-up. The first advertised surface is `delegate d:t`, `t.parent`/bare `parent`, own/delegate-chain reads and replacement stores, raw membership, normal method receiver binding, own newslot/delete, shallow clone retaining the delegate, and safe error/cycle handling. This does not claim metamethod or default-native-method parity. Reached unsupported hooks/default closures must remain explicit uncatchable policy refusals, while dead hooks must not reject otherwise admitted execution.

This is smaller than immediately implementing every metamethod: the latter also needs nested root frames, non-suspendable operation debt, branch-specific ignored hook failures and error-object retention, and native/script callback ownership. Those are real prerequisites, not ordinary calls with another function name.

An alternative is default table methods (`len/rawget/rawset/...`) first. That is independently useful but does not unlock explicit delegates: it needs shared default-delegate native-closure storage, registration metadata and native-body receiver handling. Language `delegate`/`parent` already exists in the pinned compiler, so neither host APIs nor default methods must precede explicit delegation. A storage-only internal atom is the safest first commit; it is not a publishable language-completeness claim by itself.

Expression `in` is currently absent from Rust even though `TokenKind::In` exists for foreach. Implement it in its own atom rather than overlooking it or treating the current foreach token as proof of support. It provides a useful metamethod-free chain oracle. If root prefers an even narrower first public surface, it can leave expression membership explicitly unported, but then all membership-dependent cases remain RED and cannot be included in the first claimed corpus.

Tables own nodes independently from a single nullable delegate reference. They do not copy inherited entries. Own null values are present slots, not lookup failure. Detaching a delegate changes all aliases of the same table. Adding an own slot shadows a delegate key; deleting that own slot can reveal it again. Ordinary method lookup may find a closure through the delegate chain, but PREPCALL still supplies the original receiver as `this` (`sqvm.cpp:853–874`).

A default table native method can be found while recursively looking through a delegate before the child receiver's `_get` is considered. Do not flatten the sequence into “walk all own slots, then invoke one hook.” Raw membership similarly must not reuse a default-method lookup. Root fallback is based on exact receiver/current-this identity; an explicit configured-root object reached through another receiver is not a license for recursive root fallback.

## Data widths and guard boundaries

The reused original build fixes SQInteger to64 bits, SQFloat to32 bits,64-bit pointers and enabled GC. SQInstruction carries unsigned8-bit arg0/arg2/arg3 and signed32-bit arg1; delegate and parent instructions use register indices in those fields and zero unused arguments. Preserve native compiler target aliases and evaluation order rather than widening instructions or hiding malformed ranges. `_delegate` is a nullable strong SQTable pointer; Rust uses an internal generation-checked heap Edge, never an integer-cast native pointer or a strong Realm cycle. Refcounts and object IDs remain existing checked ownership metadata, not script values.

Operation debt is signed64-bit and may legitimately be negative after a non-suspendable hook. Do not clamp it to zero or charge a hook as one instruction. Existing checked Rust budget overflow and native-undefined arithmetic/index conversion guards stay uncatchable. The design does not authorize limit/overflow or invalid-call probes; source-bounded ordinary receiver/type/cycle refusals are distinct. Nested native-call depth and CPU-error thresholds belong to the later hook boundary, not a justification to run uncontrolled recursion.

## Ownership prerequisite and Rust seams

Current `Object::Table(Nodes)` in `heap.rs` has no delegate edge. Introduce a cohesive private table storage structure (`table/data.rs` or equivalent) containing the existing physical Nodes and an optional same-realm internal heap Edge. Keep public `Table` identity/handle representation and existing raw table APIs. `new_slot`, `raw_get`, `set_existing`, `delete_slot`, `len`, `next` remain own-storage operations; VM delegation is a separate responsibility. No new public host-delegate API is needed for the proposed first script surface.

Marking must yield the delegate edge before node value edges. Aggregate keys remain outside admission; current scalar key storage is unchanged. A stored Edge must not retain Realm strongly. A public/VM parent result acquires an external handle only when published, like other returned graph values. Delegate-chain validation can use numeric heap object identities and bounded read borrows; it must not allocate temporary public owners or keep RefCell mutable borrows across release/finalization.

There must be explicit ordinary-destruction versus GC-finalization paths. A single appended field with Rust's automatic drop order cannot reproduce both native orders. Ordinary destruction can release delegate before Nodes; GC must clear own values then detach delegate, retaining the existing GC current-object guard and draining the existing deferred free queue at source-defined boundaries. Examine `Heap::collect`, `release_pending`, `ownership::Edge::drop`, and the current collector's admitted root-order limits before editing. Existing collection batches internal edge release until its drain; the new delegate/value interaction needs an actual owner oracle, not an assumption that one final heap count proves order.

SetDelegate first checks same-realm Rust safety (no native cross-VM misuse is exercised), validates the delegate-only chain, retains replacement, swaps/releases previous edge with no active invalidating borrow, and publishes the result last. Reassigning the identical delegate must not transiently free it. Direct/transitive cycle refusal leaves all prior graph edges unchanged. Legal cycles via slots, arrays, closure captures/defaults, root bindings or retained thrown Values must remain collectable. Cloning retains shared delegate identity; own node capacity/physical reinsertion order stays unchanged.

Current `Realm::collect_cycles`, private watch/reference probes, host root slots, Runner error Value and closure capture tests provide Rust owner test seams. Add explicit delegate cases to those seams without moving old selectors or altering expected old bodies. `runner/error_state.rs` stays the single retained last-error Value; existing borrowed `native_error_value`, byte `native_error` and const compatibility remain intact.

## Compiler and VM integration, first bounded slice

1. Storage/ownership atom: private table data and strong internal delegate edge; attach/detach/cycle/clone operations and separate finalization order; direct owner tests. No parser enablement until this passes.
2. Membership atom: lower expression `in` at native LogicalAndExp level, maintaining left-to-right mixed `&&`/`in` control flow and exact native bytecode/register aliases. Do not insert a guessed rank into TokenKind::binary. Add0x29 raw lookup for currently admitted receiver types, exact temp ownership and no configured-root fallback. Existing float-index/hash conversion guards remain uncatchable. Foreach syntax stays unchanged.
3. Delegate language atom: lexer tokens; factor `delegate` and bare `parent`; `.parent` source restrictions; opcodes0x35/0x21 with exact register and unused-field validation. Existing compile API/error structure remains. Use source diagnostics through established CompileFailure/native_failure paths, not fixture-name replacements.
4. Route ordinary lookup/replacement through coherent VM delegate-chain routines shared by GET/GETK, PREPCALL/PREPCALLK, Symbol capture and compound update. `roots.rs`, `calls.rs`, `closures.rs`, `updates.rs`, `objects.rs` must agree. Preserve configured root/constants order, field-update ignored Set-false behavior, temporary lifetime and one-dispatch accounting. No recursive Rust VM or separately constructed Runner for hooks.
5. After product/direct tests freeze, add mandatory source closure/contract assets and admitted fixtures with exact current hashes in a separate atom. Preserve all143 declarations/36 drivers/current1374 assets and inherited statuses. No new driver, cap change, parser relaxation, dropped source or weakening of omission/tamper checks.

A defined cycle needs a typed result (proposed additive `VmError::DelegateCycle`) and its exact catchable native diagnostic. Wrong delegate/receiver types can use established operand/receiver categories, with source wording. A distinct proposed `UnsupportedMetamethod` policy result must remain uncatchable and must not manufacture a native error Value. These are design proposals requiring source approval, not current APIs.

In particular, `Capture::Symbol` currently forwards all lookup failures through index_failure. A newly reached unsupported hook must propagate as policy refusal before that translation; real source missing-index failure must retain the shared renderer and49/50/51/60-character B1 behavior. Do not infer present failure from the Runner's historical error object. Malformed internal opcodes, foreign realms and undefined numeric conversions remain guards, not script-catchable native failures.

“Reached” is essential. Own Get bypasses `_get`; raw membership ignores it; own NewSlot bypasses `_newslot`; identical-object comparison bypasses `_cmp`; table foreach ignores `_nexti`. Attaching a table that contains a hook name must not blanket-reject the table. At every otherwise reached unported hook, propagate the explicit policy result before a false native result or ordinary type-name result could be claimed. Guard table-call, unary/arithmetic/comparison/typeof, clone/delete/newslot/get/set, string conversion and symbol captures at the actual relevant source branch; preserve bypassed cases. This is a defined-but-unported boundary, never a new UB classification.

Current first-slice corpus has24 foundation bodies, ten hook bodies, five further hook/operator bodies and four default-method bodies. Some foundation assertions use `in`, making the membership prerequisite visible. The raw-in-skips-hook case also belongs in first-slice bypass admission. Hook/default bodies remain required REDs until their separate implementation, not silently removed or declared passing.

## Why metamethod calls are a separate execution atom

`CallMetaMethod` (`sqvm.cpp:1511–1523`) retains the selected immediate-delegate closure, pushes receiver/key/value arguments, calls `Call(...raiseerror=false,can_suspend=false)`, then pops arguments on either success or failure. `Call` (`1478–1509`) backs up `_can_suspend`, forces false for script Execute, then restores it. Execute starts its own root boundary/local trap counter (`693–719`), increments native recursion count, consumes the same operation counter (`740–748`), and returns/unwinds at this nested root. Ordinary script calls in the existing Rust flat dispatch frames do not implement this boundary.

Future implementation should add an explicit nested invocation frame/scope within the same Vm, same Runner, same physical registers/varargs and same operation debt. It must distinguish ordinary call return from hook return, retain caller operation continuation/results/receiver/key as actual source owners, and restrict catch search to traps installed inside the hook invocation until its root fails. Only the enclosing operation's eventual false/true decision can transfer to the caller's trap. Do not route an uncaught hook throw immediately to an outer script catch.

The hook cannot suspend when debt reaches zero. It keeps charging instructions, native bodies and nested calls; once it returns, the outer dispatcher can suspend with negative debt before its next instruction. Current `hook-budget-debt` native schedule1 shows debt at `suspend -69 8`, then `-54`, then `-23` at the same caller IP before later credit permits progress. This is not permission for unbounded native probes: all discovery hook loops are small and fixed. Native stack-depth and CPU threshold rules must be designed independently before any such stress case; none is credited here.

Trap/error ownership is branch-specific. `_get` failure may be replaced by an index diagnostic, or a later root fallback can still succeed. `_set` failure may be superseded by caller index failure or ignored by compound Set. `_newslot` failure can insert a slot successfully. `_delslot` failure can remove/return an own value. `_cloned` failure still publishes the new object. Current successful captures retain last_error bytes `newslot`, `delete`, `clone`; the caught-array hook returns successfully while retaining an array error object. Never convert arbitrary thrown objects to strings to simplify this; preserve actual Value alias/lifetime and existing typed Rust error categories.

The selected hook, new clone and callback arguments remain retained over mutations that detach or replace their original delegate/root slot. Their owners must release in the same source sequence after Pop/Return/unwind; physical varargs teardown, tail-call guards, defaults/captures and inclusive ClearStack behavior remain shared with existing code. A plain convenience call to `Runner::start` would lose these guarantees and is rejected.

Arithmetic hooks dispatch on reached left receiver; comparison `_cmp` is not equality and only relevant source type/identity branches call it. `_typeof`, `_tostring`, `_call`, `_unm` each have distinct result/fallback rules. `_nexti`, `_newmember`, `_inherited` are not a license to add classes/generators/userdata. Their admitted table behavior and future domains must remain explicit. Full arithmetic/string/ordering hooks are a later follow-up after the nested execution atom and get/set/newslot/delete/clone family, not part of the first ordinary-delegation claim.

## Default table methods and C API distinctions

`sqbaselib.cpp:381–420` registers table len,rawget,rawset,rawdelete,rawin,weakref,tostring,clear; there is no table `setdelegate` method in this fork. SharedState creates and roots one default table with native closure identities (`sqstate.cpp:72–88,143–152,282–291`). Ordinary lookup must eventually return those same identities/metadata, not synthesize a new function per lookup. Current NativeFunction has four bare-root builtins; parameter-check/type-mask/environment/receiver assumptions must be extended through a coherent registration descriptor when this separate slice is approved.

`rawget`/`rawin` use `sq_rawget` (`sqapi.cpp:864–895`) and do not traverse table delegates. This differs from language raw `_OP_EXISTS`, which does traverse them. `sq_rawdeleteslot` returns null on missing own key and succeeds (`815–835`), unlike language Delete's error. `Clear` preserves delegate. `sq_setdelegate` (`791–814`) has its own stack protocol and the literal diagnostic `delagate cycle`, distinct from0x35's `delegate cycle detected`. Do not compare a C API error to a language-opcode error or port host APIs as an accidental prerequisite.

Default native closure receiver is frame slot0; existing root builtin bodies largely consume the first explicit argument. Metadata and borrowed receiver handling must be source-derived, preserving old four builtins and frame/native cost rules. Weak references, arbitrary default closure environments and persistence remain future boundaries unless separately source-approved.

## Oracle and meaningful controls

Use the already audited original standard observer, copied byte/mode exactly from167's seal; do not rebuild OpenTTD or patch the VM. It reports raw bytecode/literals, operation debt, suspend positions, terminal values and passive typed last-error snapshots. It reads `_lasterror` directly with type dispatch; runtime stderr reads string storage only for OT_STRING. It never calls sq_getstring on an arbitrary error. Whole error-object graph identity/lifetime is not exposed by this observer; `last_error unsupported 134217792` is a type observation, not graph proof.

The52 final source bodies (43 delegation/hook/default plus9 independent membership) are small, fixed and defined: scalar results/assertions, valid Unicode/NUL string keys, finite integer operations, bounded loops, ordinary arrays/tables, source-generated bytecode and well-formed calls. Attach/type/cycle/delete refusals are native source-checked branches. No crafted bytecode, aggregate hashing, out-of-range numeric conversion, tail badarity, sanitizer or known17lexer-UB case is used. Each corrected body must pass native source assertions before its Rust mismatch receives RED credit; three schedules and debug/release copied Rust observers preserve exact raw channels.

Required future controls include:

- Rehashed raw runtime/compile stderr mutation and a bytecode/suspension/credit mutation; genuine current strict producer must reject, restored bytes must pass. Retain actual failed success-expecting assertions, never change expectations to Unsupported.
- Replacing/detaching delegate after an alias or capture; setting inherited existing slots versus own newslot; deleting own/inherited; clone shared delegate with independent nodes; own-null presence; parent result identity; root fallback and full source evaluation order.
- Cycle direct/transitive refusal leaves graph unchanged. Delegate-only cycle rejection must not reject legal slot/closure/error cycles. Same-delegate reassignment must not release sole owner.
- Borrowed/native owner witness for immediate release versus collection: delegate-only retention, displaced delegate release, old/new identical edge, cloned shared delegate, table→delegate→owner slot cycle, closure/default→delegated table cycle, retained error Value holding the last reachable table. Rust private watch/reference probes and Realm::collect_cycles must consume actual original captures.
- A minimal source-approved passive owner observer must record refcounts/stable identities at live boundaries and never dereference released objects. Reuse established weak observation/owner patterns with explicit observer-effect accounting; do not use sq_getdelegate/AddRef as if observing borrowed counts were neutral. Native ordinary destruction and GC Finalize orders require separate controls. This observer is not written or executed in the design-only task.
- Qualified `::assert` and `::events` inside `_get` observers avoid recursively intercepting their own instrumentation. Validate a positive baseline before each mutation. Preserve failed exploratory sources, not just corrected cases.
- All new helpers/fixtures/source inputs become mandatory hashes/copies/modes; meaningful omission/byte/owner-execute tamper controls at real admission points. Existing17×9 policy receipts and normal16 corruptions stay intact. Full previous workspace/Python/static/native compiler/runtime/call/closure/varargs/trap/owner regressions remain required after implementation.
