# Native root oracle and proposed Rust observation boundary

This observer increment executes finite source-defined root experiments on OpenTTD 15.3, pinned commit `14ec60f248547d4d062a1160f0fc26d742319888`. It does not implement shared-state graphs, native contexts, RefTable, nested Execute, hooks, or default delegate methods in Rust. The approved roadmap remains `script-roots-design.md`.

## Actual native observation

`native_roots_trace.hpp` reads borrowed live SQObject fields and public physical VM storage. It reads string views only after OT_STRING dispatch. It never calls Get, Next, sq_getstring, or creates a string/reference owner to observe. Unknown chain nodes remain `?`; chain traversal never casts a node to infer its type. Thirteen shared tables and primary VM use fourteen distinct recorder registrations within the unchanged sixteen-label capacity. Root table registration uses a separate session. The unchanged recorder logs label/size before free, clears registration before address reuse, and never dereferences retired pointers.

`--native-roots MODE off|on` exposes ten bounded modes: shared, idle, persistent, replace, same, friend-stack, friend-local, friend-host, refs, refs-string. Explicit AddRef/Release in the two host-token families are the experiment itself. Repeated AddRef and intermediate/final Release observe real API semantics; strings occupy real RefTable slots. RefTable private capacity, buckets, free-list and slot addresses are not exposed or inferred from chain count.

`--native-roots-active FILE ACTION RECORD` adds snapshots only at the existing active-owner before/after points. The five existing finite frame, varargs, error, closure and allocated-receiver scripts are unchanged. ACTION deliberately requests the already-approved host collection; off/on action states need not match. Recorder off/on must match all endpoints. Removing only the new `roots ` records from a new enabled capture must reproduce an independently executed legacy active command byte-for-byte. This is observer protocol checking, not normalization of a native/Rust behavioral comparison.

A snapshot emits error, error handler, debug hook, root and temporary in source marker order, every allocated stack slot (including slots above top), physical varargs, active call closures and frame counters, then labeled chain order. Scalar payloads other than the separate persistent return line are not emitted. Counts are observations, not claims about unknown object types or strong-vs-weak edges.

## Pinned source anchors and limits

- `squirrel/sqstate.cpp:74–154`: real default tables/native closures, registry/const/metamethod tables are allocated before primary VM construction. `sqapi.cpp:55–87` constructs primary/friend contexts; `sqvm.cpp:318–336` initializes physical storage, shares friend roots/handlers, then registers base globals.
- `sqstate.cpp:268–327`: actual rootVM, RefTable, registry, const, meta and ten delegate enqueue order, LIFO processing, unmarked finalization and live-chain reconstruction. `sqobject.cpp:491–501` marks error/handlers/root/temp, complete allocated stack, physical varargs and active call closures.
- `sqstate.cpp:386–515` and `sqstate.h:26–50`: real RefTable retain/release, holes, growth, pointer hash and private physical fields. `sqapi.cpp:155–173` admits the explicit tokens used here; all tokens are released before close.
- `sqvm.cpp:104–145`: reference lifetime differs from GC reachability; Finalize clears persistent fields/allocated stack/call storage. `sqstate.cpp:330–347` unlinks nodes. `sqapi.cpp:128–133` and `sqstate.cpp:156–200` define close/destruction.
- `sqapi.cpp:467–475`: root replacement consumes the actual stack entry; same-object replacement retains the input until assignment/pop. `sqapi.cpp:938–942` resets last error independently of temporary state.

The idle original process has 85 collectable chain nodes; the shared session separately observes thirteen real shared table fields. This does not classify the other nodes. Persistent caught-array error survives collection; failing compilation replaces it with a 21-byte diagnostic, successful compilation retains that error, reset clears it. The temporary here is scalar, not a claimed closure-root witness.

A local SQObjectPtr keeps an idle friend reference-live but is not a GC root. Collection finalizes the friend and removes it from the reconstructed chain. After the local drops, RemoveFromChain with its null prev/next assigns a null shared head. This experiment records only that scalar head and the genuinely primary-owned root after release. It performs no second GC, chain walk, execution or reset on the finalized friend. Close is bounded to this acyclic idle initialization graph: no friend-exclusive objects, no remaining host tokens, all survivor links live and no links to the detached friend. The report retains the pre-execution source safety argument. This is not general safe continuation credit for finalized threads.

## Current Rust interfaces, unchanged

`Realm` (`realm.rs:13–23`) owns the string pool, constants and `Rc<Heap>`; `Realm::new/default` creates no SQSharedState-equivalent graph. `Realm::collect_cycles` (`realm.rs:127–132`) discards the internal collector count. `Heap` (`heap.rs:49–72`) contains generation-tagged entries and the actual chain. `Entry` separates optional lifetime from optional object, permitting finalized-but-reference-live states.

`Life` (`heap/ownership.rs:15–21`) has generation identity, reference count and host-root count. `Ownership::{HostRoot,Reference,Stored}` preserves the public Value/Handle clone contract. Current collection (`heap/collection.rs:16–50`) starts from entries with external host owners; its comment explicitly disclaims native VM/RefTable root order. No native VM, shared default-table graph or RefTable identity can truthfully be reported from these entries.

`Runner` (`runner.rs:132–149`) is not a heap object. Its public const constructor stores one RootSlot each for root/error/temporary. It remains const and allocates/enrolls no context. `native_error_value` returns a borrowed actual Value; snapshot code must not clone it. `friend` (`runner.rs:173–176`) registers defaults on the shared root and clones that configured root. Existing registration tests (`runner/native_roots.rs`) use real table iteration/owning reads; they are useful old API tests, not a passive current shared-graph observer.

## Proposed next read-only Rust seam — not implemented or approved here

Add a cfg(test)-only `heap::observation` module whose `Heap::snapshot` borrows actual entries/chain for one bounded read. Return scalar records only: existing `(index,generation)`, object variant if present, reference/external counts, chain membership/order, and finalized-but-reference-live status. Copy scalar fields; never clone Life/Rc, Handle, Edge, Stored or Value, call a lookup that returns an owner, run collection, or hold a RefCell borrow across formatting/host callbacks. A disappeared entry is a retired generation, never a fabricated replacement identity. The caller labels only identities obtained through existing live borrowed handles; no fabricated VM/default nodes.

A separate cfg(test) Runner snapshot borrows the three RootSlot payloads and records actual value kinds/identities, without registration or materialization. Active VM observation would be a later explicitly approved extension: its register vector/frame/physical varargs storage must be directly borrowed, not approximated by source locals or logical top. No callbacks should own a Runner while VM holds its mutable borrow.

Tests must first prove the observation itself leaves reference/external counts, retirement events and old API results unchanged. Genuine success-expecting tests can then exercise current ordinary Realm/default_root/Runner construction, error-producing compile and execution, successful compile retaining error, reset, root replacement and host-owned collection. The expected native body/operation order and actual source bytes must be retained. The comparison should expose the real missing shared/VM identities as a failing assertion on an observed current graph, not call an absent factory and label its absence RED. Error/temp/source-order projections require explicit typed correspondence; unsupported fields remain an explicit gap.

The next semantic proposal must separately specify generation-context storage, all thirteen shared tables/ten delegate registries and native closures, precise RefTable layout/weak roots, primary/friend lifetime, nested Execute roots, full allocated slots, const legacy API boundaries and ordinary CLI/AI/GS adoption. The observed 85-node count alone approves none of these changes. Existing 101 hook bodies/303 native runs, 558 Rust REDs, root fallback cases and eight raw address-bearing cases remain required. No hooks/default methods or root-collection admission changes occur in this increment.
