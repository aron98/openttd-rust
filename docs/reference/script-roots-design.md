# Shared-state and VM root enumeration proposal

This is a source-first design, not implemented behavior or a gate approval. Base: `ef8b91669008a42ba0ddd7236a8abf30fa71b7c3`; original: OpenTTD 15.3 `14ec60f248547d4d062a1160f0fc26d742319888`, i64/f32 with GC. Native paths below are relative to `src/3rdparty/squirrel/squirrel/` unless qualified. The frozen active-owner prerequisite and its custody remain unchanged.

## Decision and compatibility boundary

Recommend an additive fallible **NativeSession::open(stack_size)** that creates a new native-comparable realm and its actual primary execution context before compilation, default registration, root publication, or collection. It must not retrofit arbitrary pre-existing realms: their allocation, owner and chain order already differ. Session owns the primary Runner and exposes exclusive runner access for compilation/execution, plus a borrowed/cloned Realm for ordinary value operations. The factory is a proposed name/API, not an existing entry point.

Preserve `pub const Runner::new(RootEnvironment)`, `const native_error()`, `const native_error_value() -> &Value`, existing `CompileError`, and public Value/Handle Clone ownership. A movable const constructor cannot register its future address or mutate an Rc registry. Its existing semantics remain a bounded host execution context; it does not claim `sq_open`, shared-state initialization, VM graph identity or native GC order. Do not register every unused RootEnvironment as a VM or wait until Print to register.

`Realm::new`, `empty_root`, `default_root`, standalone compile and `Vm::new` retain their existing host semantics before native materialization. Existing `Realm::collect_cycles(&self) -> ()` remains the legacy host collector for those realms; its signature cannot express a typed refusal. Introduce a separate checked native collection entry point requiring the materialized session capability. The ordinary compatibility CLI must construct a NativeSession before its first native-comparable compile, not accept a legacy realm then fall back to host collection. Any internal request for native GC without that capability fails with a dedicated typed context error before mutating the heap. It is uncatchable infrastructure refusal, never a fabricated Squirrel error. No opt-in flag or test-only enrollment establishes fidelity. On a live materialized realm, the existing collect_cycles entry point must dispatch to the complete native root enumerator as well, so an ordinary PrintSink cannot accidentally select the legacy algorithm. After session closure it may perform only host graph cleanup; checked native collection refuses ClosedContext. A native-comparable producer exclusively uses the checked live-session path and never credits that post-close cleanup as native GC.

The new factory can report allocation/context initialization failure before calling the compiler, so no registry failure is misrepresented as a CompileError. Existing low-level constructors remain callable and tested, with their bounded guarantees documented. RootEnvironment is still a table identity, not a thread identity. A foreign or already initialized realm cannot be adopted by the factory. The native-comparable collector is not enabled while shared/default graph objects are missing; empty placeholder tables are not an implementation of that graph.

Proposed public surface, subject to source approval: `NativeSession::open(initial_slots: usize) -> Result<Self, VmError>`, `primary_mut(&mut self) -> &mut Runner`, `realm(&self) -> &Realm`, and `collector(&self) -> NativeCollector`. The collector is a non-owning context capability with a generation/closed-state check; `collect(&self) -> Result<usize, NativeContextError>` reports the actual original collection count. It may keep heap storage safe but must not retain the primary VM as an additional graph owner. Its ownership effects must be measured separately from a public Value clone. This lets a PrintSink collect without borrowing the active Runner or holding a registry borrow. Existing PrintSink's void signature is unchanged; a closed/missing capability is rejected at installation/native-call preparation rather than converted into a script exception inside print. New context errors are infrastructure errors, not replacements for existing VmError/CompileError variants or their native strings. No eager enrollment of arbitrary Runner values is added to these accessors.

The native `_root_vm` SQObjectPtr owns one actual primary VM even when idle. The VM owns its root and persistent fields. A C++ local SQObjectPtr retains lifetime but is not a GC root. A friend on a live marked VM stack is reachable; after Pop a bare C++ local friend can be finalized by GC. A friend retained through `sq_addref` is independently reachable through RefTable. Keep these distinct. Existing `root_slots.hpp:70–81` uses a C++ local after Pop without AddRef, whereas `arrays.hpp` uses its explicit host-retention wrapper; their no-GC successes do not prove equivalent collection behavior.

Public Rust Clone deliberately adds a HostRoot and real owner for each clone. Do not rename that count to native RefTable.refs. A future explicit native host-retention token must model the RefTable entry/refs separately from value copies; it cannot be inferred from `Life.external`. Physical slot reuse/order must be tested, including noncollectable native entries that occupy slots even though marking skips them. Pointer-valued native hash affects lookup, not a license to invent addresses or ignore table layout.

## Proposed internal interfaces and ownership

1. **ContextId** is a generation-checked index of an actually materialized VM context record, allocated at the source VM-creation point and inserted into the collectable chain. It is not a fabricated ObjectId, table surrogate, Runner address or pointer cast. A heterogeneous marker work item distinguishes an existing heap object from an existing VM context. Numeric membership records alone own no graph values.
2. **RootSlot** owns one authoritative Value plus optional private membership binding `(ContextId, field/index)`. It has a const unbound constructor and const borrowed accessor. Binding records the current collectable identity without cloning a Value, promotes no extra HostRoot, and cannot be performed merely by observing the slot. Moves/replacements update membership and release the displaced owner in source order. All graph-ID reads validate generation and realm.
3. **RootSlots** covers actual allocated stack, physical varargs and active frame closures. Membership capacity is prepared before publishing growth or moving owners; allocation failure leaves either the specified source partial state or an unchanged transaction, chosen per original operation. A slot manifest records null/noncollectable positions too, so indexes and allocation boundaries remain verifiable. No second Vec<Value> mirrors the stack.
4. **SharedRoots** owns the actual registry/const/metamethod/default graph objects exactly once and enumerates them in the source root order. The primary context is strongly retained by this actual native session lifetime. RefTable is an explicit native-retention structure, not a filtered walk over externally owned arena objects. HostRoot references from the legacy public API remain an additional documented host extension unless expressed through the explicit native retention seam.
5. **Root snapshot** takes short registry borrows, produces ordered typed identities with no owners, drops all borrows, then marks/finalizes. The single-threaded collection operation has no callback during enumeration. No RefCell/heap borrow survives a release, finalizer or PrintSink call. Reentrancy/state checks are explicit typed errors at the boundary, not unsafe access to suspended Rust stack addresses.
6. **Execution attachment** borrows the primary Runner while a Vm is active. Context membership survives suspension and Vm completion; only active slot/frame portions are detached or cleared according to source. A fresh nested Execute attaches to the same context and physical stack, not a second primary root. A Drop guard cleans attachment on every Rust return/error path without silently rewriting source-preserved slots.

For the first existing-path implementation, the primary Runner's authoritative fields remain directly owned and borrowable. Its context cannot be finalized while the session is live because `_root_vm` is the real root. A public materialized friend wrapper must carry an explicit native host-retention token while it exposes borrowed Runner fields; that is the source analogue of a host `sq_addref`, not an invisible extra root. It must not pretend to model a bare unrooted C++ local. Ordinary Runner::friend remains the legacy bounded API until an explicitly named native friend constructor and its retention contract are added.

Internal unrooted thread values require owned context storage that the collector can finalize safely without invalidating any public `&Value`. Do not put all Runner values behind RefCell and return borrowed references through it, or mutate a borrowed Value during Realm collection. The private thread/context representation and retained-versus-unretained friend oracle are a prerequisite to native thread/default-method admission. No public unrooted friend borrow is proposed. Dropping a session closes its primary context in source order; exported public host Values can remain memory-safe with finalized native contents, but the closed session cannot resume, compile or collect natively. A cloned Realm does not keep an apparently open native VM after session closure.

The assignment ordering primitive must reserve required metadata first, retain/move the incoming real owner, publish authoritative value and matching membership, then release the old owner without a registry borrow. Audit assignment aliasing and same-object replacement against native SQObjectPtr before implementing; numeric membership publication alone is not an ownership event. A RootSlot extraction is a separate mechanical atom with body/selector equivalence before semantic reclassification.

## Persistent and active state transitions

| State/operation | Root and owner obligations |
| --- | --- |
| New native session, idle | Primary context already registered and rooted; real initialized root, shared tables and allocated null stack exist. Error/temp/handlers are exactly initialized values. No compile or Print needed to make them visible. |
| Compile failure | Replace retained error with the exact native compiler string; preserve temporary and root. Native error Value is authoritative; Rust failure history is not a separate graph owner. |
| Compile success | Retain previous native error and temp. Returned program host retention and compiler intermediate references are distinct; no eager-rooting all compiler locals. |
| `reset_native_error` | Clear the error slot and membership together, release its actual owner, preserve typed history. Native `sq_reseterror` is `sqapi.cpp:938–942`. |
| Root replacement | Check realm before mutation; publish new root/membership and release old root in assignment order. An alias remains the same identity. Never native-run GC with a null primary root under the pin's WITH_ASSERT CountUsed assumption. |
| Start/resume/suspend | Preserve allocated slots, physical varargs, active call closures, host prefix and stale slots the native source still owns; update every write/growth/clear, not a Print-only projection. Resume does not create another context. |
| Return/uncaught failure | Preserve native source cleanup bounds and persistent temporary/error. Frame retirement does not unregister the persistent VM. Current Rust terminal all-register clearing needs explicit native comparison before replacement. |
| Idle collection after result drop | Retained temp/error/root and actual host RefTable entries still root graphs. C++ locals/private reference operands do not. Borrowing `native_error_value` adds no owner and must remain safe across collection. |
| Friend create/drop | Share root/handlers at Init, register defaults in source order, root through actual caller stack or explicit host token; membership existence itself adds no GC root. Drop token and owner separately. |
| Session reset/close | Execute native host teardown then shared teardown; invalidate context generations after real retirement. Reset constructs a new native lifetime, rather than reusing stale registrations. |

## Execute, native frames and error propagation

`sqvm.cpp:341–437` specifies argument/default moves, physical varargs, call-frame closure ownership, growth and return cleanup. Native stack growth (`newtop + stacksize * 2`) must be represented as allocated slots, not just Vec capacity or live register count. HostStack's present Vec<Program> is a public host abstraction; cloning it into a root snapshot adds owners and cannot model the actual physical prefix. Source-correct prefix membership must follow real Push/Pop slots and origin arithmetic.

`sqvm.cpp:691–749,1055–1106` gives each Execute a local trap count and root-frame boundary while sharing VM stack, last error, temp and op counter. The local `currerror` is a reference owner, not an extra root; the VM's actual last-error slot may separately retain the same object. Error handler execution can replace that slot while a local error survives. Preserve catch-target assignment, trap pop, inclusive ClearStack, vararg/frame unwind, and final last-error replacement in source order. A live local reference may survive finalization with native-cleared contents; never promote it merely to keep conventional container behavior.

`sqvm.cpp:1120–1227,1478–1522` separates handler pushes, native call frames and CallMetaMethod's local closure owner. Native arity/type checks precede frame publication; native call disables suspension around its body, then restores frame/base/top and cleans the literal source range. CallMetaMethod performs fresh Execute with suspension disabled, shares operation debt, and pops arguments after success or failure. It is not ordinary `script_call`. Every nested Execute has its own trap/root-frame state, but does not mint fresh credits or new shared roots. Current single-loop script calls and unconditional Rust debt suspension do not implement this path.

Error/debug handlers, weak closure environments, native default closures, thread/generator/class/instance roots and full compiler-constant table storage are not present in the current Rust model. Their enum variants and concrete strong/weak edges must precede admission of their operations. The BTreeMap constants pool is not the native const table. Do not manufacture tables/closures with fake behavior merely to make root counts look right. Root registry infrastructure alone does not close these dependencies or the full 48 native defaults.

## Production adoption and startable atoms

Native game source is explicit: `src/script/squirrel.cpp:510–544` constructs `sq_open(1024)`, handlers, root stack entry, global library and const-table delegate; `:717–745` removes delegate, pops root, closes, and resets by reinitialization. `src/script/script_instance.cpp:51–77` creates Squirrel before API registration/loading; `src/ai/ai_instance.cpp:37–49` and `src/game/game_instance.cpp:32–44` use that path. Bare Squirrel compatibility and OpenTTD game hosting are distinct configurations, not extra globals silently installed into every bare VM.

A. Extract persistent RootSlot/slot-write responsibilities in `runner`, `vm/roots`, `vm/registers`, `vm/traps`, with unchanged bodies/inputs/selectors and const/API compile tests. No collector switch or admission change. Then add generation-checked context/root membership and native-session lifecycle in coherent modules under 250 pure LOC, including idle/error/reset/close tests; refuse native collection until its complete graph is initialized.

B. Port actual shared-state/default registry storage, stable native identities and explicit RefTable retention (including weak-reference prerequisites) in source allocation/lookup/mark order. Existing native closures remain distinct and precise unsupported invocation remains until their genuine implementation; placeholder success is forbidden. Define private thread contexts before unrooted thread operations. Test original identities/count/order, shared-vs-independent realms and physical RefTable slot reuse. This atom's detailed data layouts remain governed by the full hooks proposal and require source approval before implementation.

C. Reclassify only audited persistent/physical VM owners from HostRoot to source Reference/Stored roles, updating every writer and whole-allocated-stack membership. Implement source-shaped active/native frame and nested Execute attachment, unwind and shared-debt behavior with genuine failed comparisons first. Keep legacy public Clone, typed errors and error bytes intact. Enable native collection only once the complete source graph and ownership oracle pass; not after a subset of five root witnesses.

D. Make `examples/observe.rs:39–50` use the factory before compile and `:148–180` formatting execution use an explicitly materialized context. Audit every Runner/Vm/Realm construction caller; pure unit host tests can retain the legacy seam, all native-comparable recipes must declare their actual construction. Future Rust AI/GS engine creation must instantiate the game configuration before registration/loading, matching the original host chain above. No AI/GS engine implementation or parity claim is included in this proposal.

E. Only after semantic freeze: mandatory source inventories/copy/mode guards for every new helper, normal producer/current Cargo selections and all established negative controls. No metadata, source cap, status, driver or parser changes are authorized by this document. Existing 143 scenario declarations/36 drivers and all requirements remain intact.

## Required oracle matrix and current limits

Use the approved fixed ASCII PrintSink host collection action and the existing preallocated passive free recorder. The action deliberately changes GC behavior; only recorder off/on within the same action must be neutral. No native core patches, temporary AddRef/Get owners, reading freed pointers, mutation through sq_getstring, scheduler hooks or unsafe cases. Additional observer exposure requires a separate exact proposal before implementation.

Required new genuine REDs before semantic atoms: (1) idle primary root/error/temp after result/program handles drop; (2) compile failure then success then reset with borrowed error identity and unchanged history; (3) two contexts sharing a table versus two independent states, both native friend retention modes; (4) complete stack size greater than top, stale receiver, closure/default/vararg/frame-only roots; (5) repeated AddRef, intermediate Release, last Release, physical slot reuse/resize; (6) native nested Execute and error-handler collection while outer local error is not rooted; (7) root replacement/same edge and session close/reset with live public aliases. Expected outputs include actual CountUsed and own-key reads separately, live refcounts under real owners, labeled chain order, finalization/retirement events, exact error bytes, op debt and callback count.

Mutations must remove each real root class individually, promote a private local falsely, truncate allocated scan to top, reorder roots/children, add a duplicate owner, miss reset/compile replacement, treat every friend as primary, retain stale generation, and suspend/reset debt inside nested Execute. They must fail genuine source-backed assertions and pass after restoration. Compare alias/identity relations and native formatting for address-bearing values; do not normalize raw process addresses or classify them undefined.

Fresh design evidence reuses the exact frozen native executable for 64 actual processes (16 finite existing sessions × action off/on × recorder off/on). Existing six prerequisite Rust tests run in both profiles against those fresh files. This establishes only the existing reached paths: internal operand, reference-live finalized containers/closures and five active root witnesses. It is not a new broader root-registry RED/GREEN and not a new build. Raw receipts, exact binary modes/hashes and source copies are in the accompanying report.

The 101 valid hook/default bodies, 303 native runs, 558 Rust discrepancies for deterministic cases, six root-fallback discrepancies and eight address-bearing outputs remain required from the frozen hooks design. This proposal admits no new execution. Full table metamethods, weak references, defaults, classes, generators, libraries, host scheduling, persistence and AI/GS remain required future work. All seven Stage04 gates remain OPEN. Root must approve this complete proposal before any production/root/evaluator change.
