# Proposed empty vanilla consist after-load boundary (source approval pending)

Base 86abaa110a8e9d919622261a7c760b9b0000ee92; native 14ec60f248547d4d062a1160f0fc26d742319888 (OpenTTD15.3). This is an executable source-design/fixture/RED increment only. Existing `rail::restore` and its single-locomotive domain/API remain unchanged. No train movement implementation or SimulationRuntime admission is proposed.

## Boundary choice

A separate `rail::restore_consists(&mut World) -> Result<RailConsistCaches, RailRestoreError>` is recommended, rather than widening `restore` or exposing an incomplete SimulationRuntime. It owns complete local train graph validation, load-order link reconstruction, train cache publication and the native saved-field edits, staged in one World transaction. Result records are ordered by vehicle pool ID, with root/chain topology explicitly represented; within a consist all calculations follow saved `next` order, never pool order. Alternatives: widening old API breaks its one-cache return/domain; general SimulationRuntime admission wrongly implies movement/unrelated runtime restoration. Both are rejected for this increment.

Initial admission: no NewGRF configuration or callback-dependent properties; current vanilla catalog; only train VEHS records; exactly one front-headed complete acyclic chain; every train owned by a valid company and all chain parts have the same owner. Every chain root has Front+Engine, no FreeWagon. Every part is a valid original singlehead engine, normal wagon or well-formed paired multihead part. No articulated parts (vanilla cannot construct them), invalid/unmatched multiheads, inconsistent sprite/subtype, orphaned wagon or overlapping chains. All front engines stopped, zero speed, not crashed/hidden; nonfront stopped bits are NOT required because original wagons/rear units lack that bit. Original subsidiary engines may retain Stopped. Every part has valid existing rail tile, same straight track axis/direction, level height and matching owner, compatible normal rail with original steam/diesel/wagon spec. No bridges/tunnels/stations/depot leftovers, electric-override rail flags, reversing/stuck/geometry repair, orders/shared orders/order backups, nonempty cargo packets/reserved cargo, or callback-defined wagons. All cargo types are valid native cargo identities; preserve each unit's original cargo/refit subtype and saved capacity. Empty cargo is a declared limit, not a zero-filled cache substitution.

Multiple roots can be admitted only when the entire roster validates before publication. First fixture corpus exercises one root and real multiple engines/pairs in that root; a separate multi-root native witness is required before claiming arbitrary multi-root support. A smallest production alternative is exactly one complete root per World, with typed refusal for additional roots until witnessed. Root provisionally selected the bounded one-root scope; first production is one root, keeping internal result ordered for later extension.

There is NO stored braking cache. The saved per-part `gv_flags` is U16 (`vehicle_sl.cpp:807`); `ground_vehicle.hpp:117–131` checks GoingUp first, then GoingDown with else-if, accumulating signed int64 slope resistance in chain order. A flat current map tile alone does NOT establish these saved flags. The proposed first boundary must explicitly refuse any part with `(gv_flags & 3) != 0` before cache/getter publication; it does not fabricate zero slope resistance or claim up/down semantics. Authentic corpus checks every saved `gv_flags == 0`, and Rust-only up, down and both-bit controls record current refusals. The public stopped getter is proposed only with this proven flag restriction. `GroundVehicle::GetAcceleration` (`ground_vehicle.cpp:103–196`) is a public read-only getter deriving current force/resistance and AS_BRAKE from Stopped/reversing/stuck. Observer records it only for fronts with valid restored weight/geometry, explicitly as derived braking acceleration. Porting this getter is a separate decision from the after-load saved acceleration byte; do not equate them. It uses int64 power*746/resistance, zero-speed force=max(power,mass*8+resistance), negative braking division with truncation toward zero and int32 clamp. Initial cache API may expose the source-grounded derived result separately if approved; no train tick is enabled.

## Articulation and callbacks

`articulated_vehicles.cpp:75` CountArticulatedParts returns0 when ArticEngine callback flag absent; `:336` AddArticulatedParts returns immediately. EngineInfo callback_mask defaults empty (`engine_type.h:210`), original table uses that default. Multihead native constructor (`train_cmd.cpp:727–763,834`) creates rear unit directly and does not invoke articulated construction. Actual fixture checks all original rail callback masks empty and no constructed part articulated. Therefore no authentic vanilla articulated success fixture exists. Articulated-bit corruption is Rust-only refusal; never call native on it or invent callback/spec results. NewGRF property0x36, refit capacity, length, visual effects, user data, sprite overrides, powered wagons, curve modifiers and dynamic engine mapping remain explicit refusal boundaries.

## Source readers and transaction design

Read each TableSchema/TableRecord through typed common/train readers: train type u8, sparse ID u32; next/orders/shared u32 wire references; subtype/sprite/cargo/cargo_subtype/owner/direction/acceleration/vehstatus u8; engine/cargo_cap/refit_cap/current_speed/rail flags and per-part `gv_flags` u16; tile and common-train X/Y u32 (vehicle_sl.cpp:662/664, range-checked into admitted nonnegative i32 coordinates), Z i32 (line666); cargo packet references and four uint32 action counts. Validate engine bounds/type/class/railtypes, valid cargo and company, settings train_slope_steepness/wagon_speed_limits/train_acceleration_model, map tile railtype/track/owner/slope and order contexts before invoking any formula. Preserve all unsupported saved fields verbatim. Stage per-part PoweredWagon flags, root saved acceleration and any explicitly admitted linkage normalization in one transaction; currently normalization branches are refused so pointers only appear in runtime result. No root-owned core World API edits required.

Typed refusal categories should distinguish roster, invalid graph/pair/subtype, callback/content, cargo/orders, ownership and track/motion. Structural graph rejection may occur at World::edit_batch/decode first; report that layer honestly. Existing RailRefusal variants must remain compatible; additions or a separate consist error type can avoid changing existing semantics. Tests record whole saved bytes and full derived state before/after each invalid edit/restore, not merely one mutated field.
